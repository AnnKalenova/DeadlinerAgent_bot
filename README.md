# Дедлайнер — голосовой ассистент для задач и встреч

Telegram-бот, который ведёт задачи, напоминания и встречи. Ему можно писать текстом или отправлять голосовые сообщения, в свободной форме на русском языке.

**Бот:** [@DeadlinerAgent_bot](https://t.me/DeadlinerAgent_bot). Работает на сервере круглосуточно.

Как бот устроен и почему так: [ARCHITECTURE.md](ARCHITECTURE.md).

## Как проверить

1. Откройте [@DeadlinerAgent_bot](https://t.me/DeadlinerAgent_bot) и нажмите «Запустить».
2. Отправьте голосовое или напишите по очереди, например:
   - «Напомни мне завтра в 10 утра позвонить Ивану»
   - «В четверг в 11 у меня встреча с дизайнером»
   - «А перенеси её на пятницу в 12:00» (бот поймёт, что речь о встрече выше)
   - «Поставь встречу с Иваном завтра» (бот спросит время)
   - «Что у меня на этой неделе?»
3. Для поиска по старым записям загрузите данные из задания командой `/demo` (1000 записей) и спросите:
   - «Когда у меня была встреча с Иваном?»
   - «Я когда-то ставил задачу по договору, найди её»
4. Кнопки внизу: «Сегодня», «Завтра», «Неделя», «Все записи» (листание по неделям и фильтры).
5. `/voice` включает ответы голосом, `/clear` удаляет все ваши записи.

У каждого пользователя свои записи, поэтому проверять можно одновременно.

## Что выбрано

| | |
|---|---|
| Язык и стек | Python 3.10+, aiogram 3 |
| LLM | Yandex AI Studio, по умолчанию Alice AI LLM (задаётся в `YANDEX_LLM_MODEL`), вызов инструментов (function calling) |
| Распознавание и синтез речи | Yandex SpeechKit |
| База данных | SQLite |
| Архитектура | голос, LLM, бизнес-логика и хранение — отдельные слои, подробно в [ARCHITECTURE.md](ARCHITECTURE.md) |
| Поиск по старым записям | совпадение основ слов + смысловая близость эмбеддингов Yandex |
| Интерфейс | Telegram-бот: текст, голосовые, кнопки; напоминания и утренняя сводка приходят сами |

## Решения и что улучшить

Главные решения (подробно — в [ARCHITECTURE.md](ARCHITECTURE.md#принятые-решения)):

- Модель только выбирает одно из шести действий и заполняет параметры, а проверяет и записывает данные код. Если модель недоступна, запрос разбирают правила, и бот продолжает работать.
- Модель получает календарь на две недели вперёд, чтобы не высчитывать даты сама.
- Если данных не хватает, бот задаёт уточняющий вопрос (время встречи можно выбрать кнопкой). Вопрос хранится в базе и переживает перезапуск.
- Удаление только с подтверждением, пересечение встреч — предупреждение, а не запрет.
- Напоминания хранятся в базе и приходят сами, в том числе пропущенные после перезапуска.

Что улучшили бы при наличии времени: замер качества на реальных фразах и подбор по ним порога поиска, свой часовой пояс у каждого пользователя, синхронизация с Google Calendar или CalDAV, сложные повторы («по будням»), потоковое распознавание длинных голосовых.

## Запуск

Для проверки ничего ставить не нужно, бот уже запущен. Чтобы поднять свою копию, понадобятся:

- Python 3.10 или новее;
- токен своего бота от [@BotFather](https://t.me/BotFather) (команда `/newbot`). Токен работающего бота не подойдёт: два экземпляра с одним токеном перехватывают сообщения друг у друга;
- ключи Yandex Cloud: API-ключ сервисного аккаунта и ID каталога. Без них бот тоже запустится, но только на правилах: без голоса и без поиска по смыслу.

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env             # вписать в .env токен и ключи
python main.py
```

Бот запустился, если в консоли появилась строка `Bot @… is running`. Публичный адрес и HTTPS не нужны: бот сам забирает сообщения у Telegram (long polling). База `data/assistant.db` создаётся при первом запуске.

На сервер бот ставится как сервис systemd одним скриптом, с проверкой новой версии и откатом: [deploy/README.md](deploy/README.md).

### Настройки `.env`

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | токен бота, обязательно |
| `TELEGRAM_PROXY` | — | прокси до api.telegram.org, если с сервера он недоступен напрямую |
| `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` | — | доступ к Yandex Cloud |
| `YANDEX_LLM_MODEL` | `aliceai-llm/latest` | языковая модель, нужна модель с function calling |
| `YANDEX_TTS_VOICE` | `alena` | голос для ответов |
| `TIMEZONE` | `Europe/Moscow` | часовой пояс |
| `DIGEST_TIME` | `09:00` | время утренней сводки |
| `MEETING_MINUTES` | `60` | длительность встречи, если конец не указан |
| `MEETING_REMINDER_MINUTES` | `15` | за сколько минут напоминать о встрече |
| `SEMANTIC_THRESHOLD` | `0.55` | порог смыслового сходства при поиске |

## Как бот понимает фразы

```bash
python -m eval.run_eval                 # разбор на правилах, сеть не нужна
python -m eval.run_eval --parser llm    # разбор языковой моделью, нужны ключи
```

Скрипт прогоняет 57 фраз из задания и их перефразировок и показывает, сколько из них понято правильно. Подробнее в [ARCHITECTURE.md](ARCHITECTURE.md#качество-понимания).

## Логи

Ход работы и ошибки пишутся в `logs/bot.log`. На сервере то же самое видно в `journalctl -u tg-assistant`.
