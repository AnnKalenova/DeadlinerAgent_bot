# Архитектура и решения

## Коротко

Telegram-бот на Python (aiogram 3). Голосовые сообщения распознаёт Yandex SpeechKit. Что хочет пользователь, определяет языковая модель Yandex AI Studio (по умолчанию Alice AI LLM, задаётся в `YANDEX_LLM_MODEL`): она выбирает одно из шести действий и заполняет его параметры. Само действие выполняет обычный код с проверками. Данные хранятся в SQLite. Если модель недоступна, запрос разбирают правила на регулярных выражениях.

Бот работает на VPS как сервис systemd, поэтому отвечает круглосуточно и напоминания приходят вовремя.

## Схема

```
                  Telegram (aiogram, long polling)
                     │                       ▲
         голосовое   │ текст / кнопки        │ сообщение с кнопками
                     ▼                       │ (+ голосовой ответ)
  SpeechKit STT ◄── bot/handlers ──────► bot/render ──► SpeechKit TTS
                     │
                     ▼
            service.Assistant  ◄── состояние диалога (storage)
            │       │        │
            ▼       ▼        ▼
          nlu/   search    schedule
            │       │
            │       └──► эмбеддинги Yandex + основы слов
            ▼
   LLMParser (языковая модель, function calling)
            │ ошибка
            ▼
   RuleParser (правила, без сети)
                     │
                     ▼
               storage (SQLite)
                     ▲
   reminders.ReminderService ──► bot/notifier ──► Telegram
   (раз в 30 с: напоминания и утренняя сводка)
```

| Слой | Модули | За что отвечает |
|---|---|---|
| Голос | `yandex.SpeechKit`, `bot/handlers` | голосовое → текст, ответ → голосовое |
| Понимание запроса | `nlu/llm.py`, `nlu/prompt.py`, `nlu/rules.py`, `yandex.YandexGPT` | фраза → `Command`: что сделать и с какими параметрами |
| Логика | `service.py`, `schedule.py`, `search.py`, `dates.py` | проверки, уточняющие вопросы, поиск, конфликты, повторы |
| Хранение | `storage.py` | SQLite: записи, пользователи, диалог, кеш эмбеддингов |
| Интерфейс | `bot/` | Telegram: обработчики, кнопки, отрисовка, напоминания |

Ядро (`service.py`) не знает ни про Telegram, ни про конкретную модель: оно получает текст и возвращает структуру `Reply`, а как её показать, решает слой бота. Поэтому ядро можно подключить к другому интерфейсу и проверять без сети.

## Где что лежит

```
main.py              запуск: читает настройки и стартует бота
assistant/
  config.py          настройки из .env
  domain.py          типы данных: запись, команда, ответ
  service.py         главная логика: уточнения, проверки, выполнение команд
  dates.py           разбор русских дат и времени
  schedule.py        повторы и время напоминаний
  search.py          поиск по словам и по смыслу
  storage.py         SQLite
  reminders.py       фоновый цикл напоминаний и утренней сводки
  demo_data.py       загрузка CSV из задания по /demo
  yandex.py          клиенты Yandex Cloud: модель, эмбеддинги, SpeechKit
  nlu/               разбор запроса: модель (llm.py, prompt.py) и правила (rules.py)
  bot/               всё про Telegram
data/                CSV из задания; там же создаётся база
eval/                замер качества понимания фраз
deploy/              установка на сервер, проверка версии, откат
```

## Технологии

| Задача | Выбор | Почему |
|---|---|---|
| Интерфейс | Telegram-бот, [aiogram 3](https://docs.aiogram.dev) | Голосовые сообщения, кнопки и уведомления есть из коробки. Проверяющему достаточно открыть ссылку. Напоминания приходят сами, а не только по запросу. |
| Понимание запроса | Yandex AI Studio, function calling | Хорошо понимает русский, умеет вызывать инструменты, доступна и оплачивается из России. |
| Распознавание и синтез речи | Yandex SpeechKit (REST v1) | Telegram присылает голосовые в OGG/Opus, SpeechKit принимает этот формат без конвертации. Ключ тот же, что и для модели. |
| Поиск | эмбеддинги Yandex (`text-search-doc` / `text-search-query`) и совпадение основ слов | Находятся и близкие по смыслу фразы, и разные формы одного слова. |
| Хранение | SQLite | Не нужен отдельный сервер, для тысяч записей хватает с запасом. |
| Клиент API модели | `openai` SDK | У AI Studio OpenAI-совместимый API, поэтому модель меняется одной строкой в `.env`. |
| Даты | свой модуль `dates.py` | Нужны русские формулировки: «послезавтра», «в следующую среду», «с 15 до 16:30». |
| Хостинг | VPS, systemd | Работает круглосуточно, сам поднимается после сбоя и перезагрузки сервера. |

## Принятые решения

**Модель выбирает действие, но не выполняет его.** Модели доступны шесть инструментов: `create_item`, `list_items`, `search_items`, `update_item`, `delete_item`, `complete_item`. Она возвращает выбранный инструмент и параметры, а код проверяет каждое поле, находит нужную запись, задаёт уточняющие вопросы и пишет в базу. Испортить данные модель не может.

**Календарь в промпте.** Модель получает даты с днями недели на две недели вперёд. Ей не нужно высчитывать, какое число будет «в пятницу», и в этом месте она не ошибается.

**Запасной разбор на правилах.** Если модель не ответила или вернула что-то неожиданное, запрос разбирают регулярные выражения. Пользователь ошибку не видит, а бот запускается и без ключей.

**Ссылки на записи по номерам.** Последние показанные записи хранятся в состоянии диалога и передаются модели пронумерованными. Поэтому «удали вторую» и «перенеси её на завтра» указывают на конкретную запись.

**Уточняющие вопросы задаёт код.** Если у встречи нет времени, у напоминания нет даты или время уже прошло, бот спрашивает и предлагает варианты кнопками. Вопрос хранится в базе и переживает перезапуск.

**Удаление только с подтверждением.** Бот всегда спрашивает «Да / Отмена», в том числе голосом.

**Пересечение встреч — предупреждение, а не запрет.** Встречи иногда действительно пересекаются, решает пользователь.

**Время без даты — ближайшее.** «В 9», сказанное в 10 утра, означает завтра. «В 3» без уточнения — 15:00.

**Напоминания хранятся в базе.** У каждой записи есть поля `remind_at` и `notified`, фоновый цикл проверяет их раз в 30 секунд. После перезапуска ничего не теряется, пропущенные напоминания приходят с пометкой.

**Поиск без отдельной векторной базы.** На тысячи записей хватает косинусного сходства в Python. Эмбеддинги считаются только для уникальных названий (в демо-файле их 376 на 1000 записей), кешируются в SQLite, а запросы к API ограничены по частоте, чтобы не упираться в квоту.

**Демо-данные.** В CSV из задания нет типа записи, он определяется по формулировке: «Встреча…», «Созвон…», «Провести планёрку…» — встречи, «Напомнить…» — напоминания, остальное — задачи. Прошедшие задачи помечаются выполненными. По демо-записям напоминания не отправляются.

**Деплой с проверкой и откатом.** Новая версия собирается рядом с работающей, перед переключением проверяется (`deploy/check.py`) и делается бэкап базы. Если что-то не так, работающая версия не трогается, а вернуться назад можно одной командой.

## Как бот ведёт себя в спорных ситуациях

| Ситуация | Что происходит |
|---|---|
| Встреча без времени: «Поставь встречу с Иваном завтра» | Бот спрашивает время и показывает кнопки 09:00–18:00. Ответить можно кнопкой, текстом или голосом. До ответа ничего не сохраняется. |
| Время в прошлом: «Напомни вчера в 10…» | «Вчера в 10:00 уже прошло. На когда записать?» |
| Вместо ответа на уточнение — новый запрос | Короткая непонятая фраза — бот переспрашивает. Длинная — уточнение сбрасывается, фраза обрабатывается как новый запрос. |
| «Перенеси её», «удали вторую» | Запись берётся из последних показанных. Если непонятно, о какой речь, бот просит уточнить. |
| «Удали задачу про договор», нашлось несколько | Бот показывает список и спрашивает, какую. |
| Перенос встречи | Меняется только названное: «на пятницу» сохраняет время, «на 15:00» — дату. Длительность сохраняется. |
| «Когда была встреча с X?» | Поиск только в прошлом, самая свежая запись первой. Если ничего нет, поиск повторяется без фильтров. |
| Модель недоступна или вернула некорректный ответ | Запрос разбирают правила, пользователь ошибку не видит. |
| Эмбеддинги недоступны или упёрлись в квоту | Поиск только по словам. |
| Бот был выключен в момент напоминания | После запуска придёт «Пропущенное напоминание». |

## Качество понимания

В `eval/phrases.jsonl` 57 фраз: сценарии из задания и их перефразировки, с ожидаемым действием и параметрами. Правила понимают 55 из 57. Две непонятые фразы оставлены специально: «Обед с Сергеем в среду в час дня» правила записывают как задачу, а «Была ли у меня планёрка по бюджету?» не узнают как поиск. Фразы писались вместе с правилами, поэтому результат правил завышен. Результат модели: `python -m eval.run_eval --parser llm`.

## Ограничения и что улучшить

1. **Оценка на реальных фразах.** Собрать запросы живых пользователей, расширить `eval` и подобрать по ним промпт и порог смыслового поиска (`SEMANTIC_THRESHOLD=0.55` пока выбран на глаз).
2. **Ответы на уточнения через модель.** Сейчас ответы вроде «в 10» или «завтра» разбирают правила, и редкую формулировку бот может не понять и переспросит.
3. **Часовой пояс у каждого пользователя.** Сейчас он один на всех и задаётся в `.env`.
4. **Интеграция с календарём.** Двусторонняя синхронизация с Google Calendar или CalDAV (Яндекс Календарь).
5. **Сложные повторы.** «По будням», «каждый второй вторник», исключения из серии.
6. **Конфликты между днями.** Сейчас пересечения проверяются только между встречами одного дня.
7. **Потоковое распознавание речи.** Голосовые длиннее 30 секунд и более быстрый ответ.
8. **Mini App с календарём.** Перетаскивание и редактирование записей мышью.
